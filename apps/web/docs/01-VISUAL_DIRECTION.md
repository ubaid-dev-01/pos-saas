# QuickPOS — Visual Direction Document

**Mode:** Design Research only. No UI implementation.  
**Standard:** If Apple / Figma / Stripe / Linear / Vercel / Shopify / Framer senior designers would reject a principle, it does not ship.  
**Anti-goal:** Generic AI SaaS template. Cartoon. Neon. Blob. Icon carnival. Oversized display type as the product.

---

## 1. Research method

We did not copy layouts from Apple, Stripe, Linear, Notion, Vercel, Raycast, Framer, Figma, Slack, Dropbox, Shopify, Square, Toast, Clover, Intercom, Ramp, Mercury, Retool, Clerk, Supabase, GitHub, or OpenAI.

We extracted **operating principles**: how they use grid, type, space, color, motion, product imagery, and trust.

| Company | Principle we keep |
|---------|-------------------|
| **Apple** | One idea per viewport. Product is the subject. Typography captions the object. Scroll = chapter turns. Hero budget is sacred. |
| **Stripe** | Diagrams that teach systems. Editorial type. Precision over personality gimmicks. Color is sparse and meaningful. |
| **Linear** | Obsessive spacing rhythm. Soft surfaces. Calm density. UI chrome is quiet; content is sharp. |
| **Notion** | Friendly gravity without childishness. Empty space as invitation. Components feel like tools, not posters. |
| **Vercel** | Engineering aesthetics: black/white discipline, monospace as signal, zero ornamental illustration. |
| **Raycast** | Product-first. The interface *is* the brand moment. No lifestyle filler. |
| **Framer** | Motion as explanation. Canvas and composition awareness. |
| **Figma** | Multiplayer clarity. Purple/brand as accent only. UI frames as truthful objects. |
| **Shopify** | Merchant trust. Commerce realism. Features framed as store outcomes. |
| **Square / Toast / Clover** | Counter intimacy. Hardware + software as one instrument. Floor truth over cloud fantasy. |
| **Intercom** | Conversational hierarchy. Human scale. Support as product surface. |
| **Ramp / Mercury** | Financial trust: restraint, hairlines, tabular numbers, no playfulness that erodes money gravity. |
| **Retool / Clerk / Supabase / GitHub** | Developer-grade clarity applied to business: docs-like scanning, honest components, no fake dashboards. |
| **OpenAI** | Quiet confidence. Vast negative space. One focal artifact. |

## 2. Positioning of the experience

QuickPOS is not a “landing page.”  
It is a **product presentation**—closer to an Apple product page or Square hardware+software story than to a YC SaaS template.

**Visitor should feel:**  
“This company spent serious money and taste on design.”

**Visitor must never feel:**  
“An AI generated a SaaS homepage.”

---

## 3. Grid system

| Token | Value | Rationale |
|-------|-------|-----------|
| Max width | **1120–1200px** content (not 1440 stuffed) | Linear/Stripe prefer readable measure; wide ≠ premium |
| Columns | **12** | Alignment spine |
| Gutter | **24px** mobile → **32px** desktop | Consistent rhythm |
| Baseline | **8pt** | All spacing snaps to 8 |
| Section Y | **96 / 120 / 160** | Fewer, larger chapters |
| Text measure | **34–40ch** headlines support; **60–68ch** body max | Never full-bleed paragraphs |

**Composition recipes (original, not copied):**
1. **Artifact center** — one product object dominates; type below or beside at ≤40% width  
2. **Split 4/8** — short copy | large stage (never 50/50 equal “blog”)  
3. **Full-bleed atmosphere** — photo or dark field with type inset on grid  
4. **Diagram band** — full-width system drawing with caption below  

Everything snaps. No free-float “creative” misalignment.

---

## 4. Composition & visual balance

- **One unforgettable visual moment per section.** If two fight, delete one.  
- **Asymmetry with anchor:** heavy visual mass balanced by quiet type + space—not by a second graphic.  
- **Eye-tracking flow (Z / F hybrid):** Brand → headline → stage → CTA. Secondary content below fold.  
- **Reading pattern:** Captions under visuals; never walls of text beside weak graphics.  
- **Balance test:** Blur the page to 10px. You should still see clear dark/light masses and one focal per band.

---

## 5. Typography rhythm

**Decision:** Kill “weird” display experiments and generic Inter-as-hero.

| Role | Direction | Notes |
|------|-----------|-------|
| UI / marketing sans | **One neutral grotesque** (e.g. IBM Plex Sans *or* Geist—pick one, not three) | Medium weight for headlines; regular for body |
| Data / SKU / money | **Matching mono** (Plex Mono / Geist Mono) | Tabular figures for trust (Mercury/Ramp) |
| Display | **Not a costume font** | No Syne-as-carnival if it reads “AI trendy.” Prefer restrained grotesque at larger size with tight tracking |

**Scale (8pt-friendly):**
12 · 14 · 16 · 18 · 24 · 32 · 40 · 56  

**Rules:**
- Brand name can be large; **headlines must not overpower the product visual.**  
- One H1 idea per page.  
- Tracking: slightly tight on ≥32px (−0.02 to −0.04em).  
- Line-height: 1.05–1.15 display; 1.5 body.  
- **No oversized poetic headlines with empty product proof.**

---

## 6. Color psychology & palette direction

**Psychology goal:** Trust, enterprise calm, retail competence—not startup play.

| Role | Direction |
|------|-----------|
| Canvas | Cool near-white / soft gray paper (not cream terracotta cliché, not pure #FFF void) |
| Ink | Near-black blue-ink (depth, not pure #000 harsh) |
| Surface | White for interactive / stages |
| Accent | **One** signal (teal *or* restrained blue)—used for CTA, focus, success moments only |
| Muted | Mid gray for secondary text |
| Danger/success | Semantic only inside product stages |

**Forbidden:** Neon gradients, purple glow SaaS, rainbow charts, dark mode as default marketing, glassmorphism stacks.

---

## 7. White space

White space is a **material**, not leftover.

- Prefer **fewer sections** with more air over many thin sections.  
- Padding inside components ≥ 16; section gaps ≥ 96.  
- If a section feels empty, **strengthen the visual**—do not add more text boxes.  
- Linear rule: if it doesn’t snap to 8pt, it’s wrong.

---

## 8. Photography style

| Do | Don’t |
|----|-------|
| Real retail counters, shelves, receipt paper, scanners | Stock “smiling cashier + tablet” |
| Soft daylight, cool grade matching canvas | Warm influencer lighting |
| Product/context primary; faces secondary or cropped | Portrait-hero lifestyle |
| Pakistan / South Asian retail honesty when relevant | Generic NYC loft |

Photography increases **trust**. If it doesn’t, delete.

---

## 9. Product mockups & device compositions

**Preferred (in order):**
1. **Editorial UI stage** — real QuickPOS screens recomposed as art (no fake metrics)  
2. **Shallow device bezel** only when it clarifies “runs on tablet/laptop”—never laptop-with-illegible-dashboard cliché  
3. **Receipt + phone WhatsApp** composition for proof of digital receipt  
4. **Architecture / workflow diagrams** drawn as Stripe-like explanatory graphics  

**Banned:** 3D laptop floating at 3/4 with neon UI; isometric office; cartoon developer.

---

## 10. Illustration philosophy

Illustrations are **rare**.

Allowed only when:
- Explaining a **system** (data flow, multi-store sync) that UI cannot show in one frame  
- Style = **minimal geometric / editorial line**—Pentagram restraint, not Storyset  

Banned: AI blobs, cartoon vectors, floating circles, random SVG confetti.

---

## 11. Icon system

- Stroke icons, **1.5 weight**, optical one family (Lucide or custom)  
- Size: 16/20 only  
- Appear **inside product UI or as inline labels**—never as a 6-up feature icon grid on marketing  
- Monochrome ink; accent only for active  

---

## 12. Motion language

| Intent | Motion |
|--------|--------|
| Explain sequence | Workflow path draw / node highlight |
| Reveal product | Mask or fade of stage once |
| Prove metric | Count-up once |
| Navigate | Shared-element restraint |

**Never:** bounce, elastic, parallax noise, infinite decorative Lottie, random Lottie for “life.”

If animation doesn’t explain a feature → delete.

---

## 13. CTA placement & hierarchy

- Primary CTA: **Start free** (ink fill)  
- Secondary: **Talk to sales / Pricing** (hairline)  
- Placement: with hero decision cluster; repeat only at true chapter ends (pricing, close)—not every section  
- Eye flow: CTA after proof visual, not before  

---

## 14. Story spine (not SaaS section dump)

Ordered narrative for the product experience:

1. **Presence** — Brand + product on the counter (hero stage)  
2. **Recognition** — The chaos they live (one problem visual)  
3. **System** — How a sale flows (one diagram)  
4. **Depth** — Few capability chapters with stages (not 12 card tiles)  
5. **Proof** — Operators / metrics  
6. **Access** — Pricing clarity  
7. **Commit** — Close  

Anything that doesn’t serve this spine is a candidate for deletion.

---

## 15. Failure modes (instant reject)

- Looks AI-generated  
- No coherent visual system  
- Random illustrations / childish graphics / random Lottie  
- Weird or costume fonts  
- Generic SaaS section stack  
- Poor spacing / no rhythm  
- Weak composition / no art direction  
- Too much text / no storytelling  
- Template feel
